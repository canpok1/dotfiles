# 0007. 相談を経て作成するタスクは着手可能な状態で起票する

- ステータス: 採用
- 日付: 2026-08-09

## コンテキスト

`docs/adr/0005-task-status-draft-ready-split.md` で「起票は常に `draft`、`ready` への昇格は人手判断のみ」と決めた。狙いは、検討が残る案件の置き場を作ることと、着手可否のレビュー機会を挟むことだった。

運用してみると後者が空回りする経路がある。`discuss` はユーザーが同席し、判断点を1つずつ確認しながら仕様を確定させるスキルである。確定した時点で「人手による着手可否の判断」は既に済んでいる。それでも `draft` で起票し、直後にユーザーが `ready` へ上げる、という二度手間が発生した。ADR 0005 を決めたその日に、続けて作成した2タスクで実際に起きている。

一方、相談を経ない起票（作業中に気づいた派生・スコープ外指摘の自動起票）では、レビュー機会は依然として必要である。

## 決定

**タスク作成が「ユーザーとの相談を経ている」場合は、着手可能な状態（Obsidian: `status: ready` / Todoist: `ready` ラベル）で起票してよい。**

- `discuss` の既定の出力は着手可能な状態とする。判断点を詰め切ることを基本とする
- ユーザーの指示で相談を中断する場合のみ、着手可否が未判断の状態（Obsidian: `status: draft` / Todoist: ラベルなし）で起票する
- 相談を経ない自動起票は、従来どおり未判断の状態で起票する

ADR 0005 の「起票は常に `draft`」はこの範囲で改定される。「**Claude は自身の判断だけで着手可能にしない**」という原則は維持する。着手可能にできるのは、ユーザーとの確認を経た場合に限る。

## 結果

良い影響: 相談の成果がそのまま着手可能なタスクになり、直後の昇格操作が要らなくなる。`discuss` の「判断点をすべて潰す」という設計と、起票結果が一致する。未判断状態のタスクが、本当に判断の残っているものだけになるため、リファインメントの対象抽出が意味を持つ。

悪い影響: 「相談を経たか」の線引きが運用者の判断に委ねられる。ユーザーが同席していても実質的な確認をしていない場合に、着手可能な状態が付きうる。ADR 0005 の決定の一部を、決めた当日に改定することになる。

## 検討した代替案

- **ADR 0005 のまま「起票は常に未判断状態」を維持する**: レビュー機会は最大化されるが、`discuss` の対話で済ませた確認を昇格操作でもう一度求めることになり、二度手間が残るため却下
- **Claude が「判断点ゼロ」を自ら判定して着手可能にしてよいことにする**: 線引きが不要になるが、人手の関与という ADR 0005 の趣旨そのものを失うため却下
- **`discuss` の中でユーザーに「着手可能にしますか」と毎回確認する**: 形式上は人手判断が残るが、判断点を全て潰した直後の確認は形骸化しやすく、実質的に前者と変わらないため却下
