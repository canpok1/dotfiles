# 0008. タスクのリファインメントを保存先非依存のスキル1つに統合する

- ステータス: 採用
- 日付: 2026-08-09

## コンテキスト

`claude/skills/todoist-triage-task/SKILL.md` は、着手可否が未判断のタスクを1件取り上げ、実施可否を判断して詳細化するスキルである。Todoist 専用として書かれている。

Obsidian でも同じ状態モデル（`draft` → `ready`）を使うようにしたため、同等の手段が要る。当初は `obsidian-triage-task` を新設する方針だった。ルールが `todoist.md` / `obsidian-task.md` と保存先ごとに分かれ、スキル名も `todoist-` プレフィックスで保存先を示す既存構造に倣う判断である。

ただし `todoist-triage-task` は7ステップ構成のうち、保存先に依存するのはステップ1（対象の抽出）とステップ6（結論の反映）だけで、残る5ステップは共通の手順である。また `discuss` は既に保存先非依存で、登録先と状態の持ち方をタスク管理ルールへ委ねる形で成立している。同じ構造をこちらにも適用できる。

## 決定

**保存先非依存のスキル `refine-task` を1つ作り、`todoist-triage-task` を廃止する。**

- 名称は triage をやめ refinement とする。実態は「仕分け」より「着手できる粒度まで詳細を詰める」作業に近い
- スキル本文には保存先固有の語を書かない。対象は「**着手可否が未判断の状態**」のタスクと表現し、それが具体的に何を指すかはタスク管理ルールが定義する（Obsidian: `status: draft` / Todoist: ラベルなし）
- 対象の抽出方法と結論の反映方法も、保存先ごとの手順としてタスク管理ルール側に置く

## 結果

良い影響: 保存先が増えてもスキルは1つで済み、共通の5ステップが二重管理にならない。`discuss` と同じ構造になり、「スキルは手順、ルールは保存先」という役割分担が揃う。スキル名から保存先が消えるため、どちらの環境でも同じ名前で呼べる。

悪い影響: スキル本文だけを読んでも具体的な操作が分からず、タスク管理ルールとの往復が必要になる。既存スキル1つの廃止にあたり、名指ししている箇所の追従が要る。保存先ごとの手順がルール側へ移るため、ルールの記述量が増える。

## 検討した代替案

- **保存先ごとに2つのスキルを持つ（`obsidian-triage-task` を新設）**: 具体的で読みやすく、既存の命名規則にも沿う。しかし共通の5ステップが二重管理になり、片方だけ更新されるドリフトが起きる。同種のドキュメントのドリフトを既に2件見つけているため却下
- **`todoist-triage-task` を残したまま `refine-task` を新設する**: 既存を壊さないが、同じ役割のスキルが2つ並び、どちらを使うか迷うため却下
- **`todoist-triage-task` をリネームするだけにする**: 変更は最小だが、保存先に依存させないという目的を満たさないため却下
