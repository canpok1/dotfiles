# 0013. 定期作業の報告は Slack、ユーザーへの確認の依頼は Google ToDo に分ける

- ステータス: 採用
- 日付: 2026-10-23

## コンテキスト

`daily-check` は、直したことの報告も、現物確認や判断の依頼も、Slack の #notification へ1通にまとめて送っていた。

2026-10-18 に依頼した間食の日曜の確認（箱の残り）は、10/22 まで毎日「未回答」と送り続けたが答えられなかった。献立・ルール化候補など他の項目と同じ1通に入り、埋もれた。

## 決定

**報告は Slack、ユーザーへの確認の依頼は Google ToDo に1件1タスクで登録する**（2026-10-23 にユーザーが指定）。

- ToDo はタイトルだけで何を答えるか分かるように書き、期限は回答が要る日にする
- 未完了の同じ確認があれば作らない。回答を受けたセッションが完了にする
- ToDo に登録できないときは Slack に出す

## 結果

確認の依頼が、ユーザーが普段見て消し込む場所に1件ずつ残る。献立以外の作業を ToDo にしている食事管理の運用（brain の `projects/meal-management/adr/0009-prep-tasks-as-google-tasks.md`）と揃う。

定期実行の環境に `canpok1/google-tasks-bridge` と接続情報が要る。無い環境では従来どおり Slack に出るだけになる。ユーザーが ToDo を見なければ防げない。

## 検討した代替案

- **確認の依頼だけ Slack の別の1通にする**: 手軽だが、Slack を見ない日は気づけないため却下
- **期限までに回答が無ければ既定値で進める**（間食なら「全部食べた」とみなす）: 確認の手間は無くなるが記録が不正確になり、判断を無人で確定させない `daily-check` の方針にも反するため却下
