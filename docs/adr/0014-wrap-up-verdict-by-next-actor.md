# 0014. ラップアップの判定を、次に誰が動くかで分ける

- ステータス: 採用
- 日付: 2026-10-23

## コンテキスト

`wrap-up` の判定は「作業終了可」と「未完あり」の2つだけだった。ユーザーへの確認事項が残っていても、こちらの作業が終わっていれば「作業終了可」と判定されがちで、スレッドが閉じられて確認が漏れた（ユーザーの指摘）。

確認事項を Google ToDo に残せば閉じても拾えるが、登録に使う `google-tasks` スキルは `canpok1/google-tasks-bridge` にあり、`wrap-up`（このリポジトリ）とは別。そのリポジトリと接続情報がある環境でしか使えない。

## 決定

**未完の項目を、次に誰が動くかで「未完あり／確認待ち／ユーザー作業残り」に分ける。**

- 確認待ち（ユーザーの回答・判断が要る）: 閉じない
- ユーザー作業残り（判断済みでユーザーが手を動かすだけ）: ToDo に登録できたら閉じてよい。**登録できない環境では確認待ちと同じ扱い**
- ToDo を使える前提にはしない（ユーザーの判断。全環境で使えるとは限らないため）
- ToDo への登録は `wrap-up` では行わず、タイトル案を示すまでにする。`wrap-up` は確認と報告だけを担当し、片付けをしない方針のため

## 結果

ユーザーの回答が要るものは、閉じられずに残るか ToDo に残る。ToDo が使えない環境では閉じられないスレッドが増える。

## 検討した代替案

- **ToDo を使える前提にする**: `wrap-up` と `google-tasks` が別リポジトリで、使えない環境があるため却下
- **`wrap-up` 自身が ToDo に登録する**: 片付けをしない担当範囲と衝突するため却下
