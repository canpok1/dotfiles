# 0009. スマホからの web クリップ受け皿に Google ドライブを使う

- ステータス: 採用
- 日付: 2026-08-14

## コンテキスト

スマホで読んだ web 記事を obsidian-vault へ蓄積したい。閲覧は Android がほとんどで、スマホに Obsidian は入れていない。vault は Private リポジトリのため、書き込みには GitHub の認証が要る。

制約として「端末に GitHub のトークンを置きたくない」「Gmail は連携したくない」の2点が示された。Android の共有シートから直接届けられて、かつ Claude が読める受け皿を選ぶ必要がある。

## 決定

**Android の共有シートから Google ドライブの「webクリップ」フォルダへ保存し、Claude が1日1回そこを回収して vault の `clips/` へ転記する。**

- 実機で確認したところ、Chrome から共有すると `text/plain`（ファイル名=ページタイトル、中身=URL のみ）で保存される。PDF 化はされない
- 転記後は元ファイルをゴミ箱へ移し、二重取り込みを防ぐ
- 回収は dotfiles の `web-clip` スキルが担う。起動はユーザーの依頼による手動実行を基本とする。定期実行にする場合、Routine は claude.ai の Routines UI から作る必要がある（Claude 側から作った Routine にはコネクタが載らず、発火したセッションから Drive を読めないことを実測で確認した）
    - **この行の「UI からなら作れる」という見込みは誤りだった。UI からもコネクタを載せられず、定期実行は見送った（0010 で更新）**

## 結果

良い影響: 端末に認証情報を置かずに済む。Drive も共有シートも標準機能のため、アプリの追加インストールも初期設定も要らない。タイトルと URL が分離された状態で届くので、転記時に本文をパースする必要がない。

悪い影響: vault に載るまで最大1日の遅れが出る。Drive コネクタと定期実行に依存するぶん経路が1つ増える。フォルダは名前で解決するため、フォルダ名を変えると回収が止まる。

## 検討した代替案

- **GitHub API を直接叩く（HTTP Shortcuts アプリ）**: 共有2タップで即 vault に入り遅延も無い。しかし fine-grained PAT を端末へ平文で置く必要があり、これを避けたい意向のため却下
- **Google Keep**: 当初の第一希望。しかし Claude のコネクタが無く、Keep API も Workspace の管理者権限が前提で個人アカウントからは叩けない。ノートは Drive にも現れず、技術的に不可能
- **Gmail の自分宛メール**: フィルタでラベルを自動付与でき運用は素直だが、連携したくないという意向のため却下
- **Todoist の専用プロジェクト**: 受け皿にはなるが、2026-08-09 にタスク管理を vault へ移したばかりのため却下
