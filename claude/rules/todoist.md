# Todoist 利用時のタスク管理ルール

## 適用条件

本ルールは、タスク（フォローアップ・バックログ・相談結果・スコープ外指摘の追跡など）の管理に **Todoist を使う場合にのみ適用する**。

- Todoist を使うかどうかは、プロジェクト側の指示（プロジェクトの `CLAUDE.md` / `.claude/rules/` / ユーザーからの指示など）で決まる。
- Todoist を使う指定がないプロジェクトでは本ルールを適用しない。**勝手に Todoist へタスクを登録してはならない。** タスク化が必要な場面では、管理先をユーザーに確認する。

以下は Todoist を使う場合の運用ルールである。各ルール・スキルはツール非依存の「タスク作成／更新／参照」として記述する。登録先（プロジェクト / セクション）とラベル運用は本ルールに集約し、Todoist への具体的な操作手段（MCP / CLI など）は問わない。

## 登録先

- プロジェクト: `dev`
- セクション: **作業対象のリポジトリ名**（例: リポジトリ `foo` で作業しているなら セクション `foo`）

リポジトリ名は git から特定する（`basename "$(git rev-parse --show-toplevel)"`）。プロジェクト `dev` と対象リポジトリ名のセクションを登録先として特定する（ID が必要な手段では名前から引く）。対象セクションが見つからない場合は、作成してよいかをユーザーに確認する。

## タスクの作成・更新・参照

- **作成**: 上記の登録先（プロジェクト `dev` / 対象リポジトリ名のセクション）にタスクを作成する。
- **参照・重複確認**: 登録先で絞り込んでタスクを検索する。
- **更新 / 完了**: 対象タスクの内容・ラベルを更新する、または完了にする。

## ラベル運用

タスクの状態管理には以下のラベルを使う。

- `<リポジトリ名>`: 対象リポジトリを示す（セクション名と同じリポジトリ名のラベル）
- `ready`: 着手してよい（対応可能）状態
- `assign-to-claude`: Claude が対応する対象
- `in-progress`: 対応中

### ラベル付与の方針

- **タスク作成時はラベルを一切付与しない** — LLM が新規タスクを作成するときはラベルを指定せず（空のまま）作成すること。`ready` を含むいかなるラベルも自動付与してはならない。
- ラベルの付与・除去は、以下の定められたタイミング・担当でのみ行う。タスク作成者が先回りして状態ラベルを付けないこと。
    - `ready`（着手可能であることを示す）: 人手で着手可否を判断して付与する。タスク着手後に作業を進められない状況になった場合は除去する。
    - `assign-to-claude`（担当者が Claude であることを示す）: タスク割り当ての評価時に、優先度評価のうえ付与する。
    - `in-progress`（着手中であることを示す）: タスク着手時に付与し、終了時に除去する。

## タスク内容の書き方

- `content`: 何をするかを簡潔・具体的に書く（例: 「重複したバリデーション処理を共通ヘルパーへ抽出」）。
- `description`: 背景・根拠を Markdown で記載する。「どのメモ / PR のどの指摘か」を必ず明記し、後から再調査コストがかからないようにする。受け入れ条件があればチェックリストで含める。
- **重複登録を避ける** — 作成前に同種タスクの有無を検索して確認し、あれば新規作成せず既存タスクへ追記する。

## 注意

- Todoist タスクには `🤖 Generated with [Claude Code]...` フッターは不要（フッターは GitHub の PR・コメント向けの規約）。
- GitHub は PR・コードレビューにのみ使用し、タスク・バックログ管理には GitHub Issue を使わない。
