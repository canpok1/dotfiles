# 開発ルール

コードやリポジトリ内のファイルを変更する作業に共通して適用する。

## 実装後の品質確認

実装したら、次の2点を行うこと。該当する目的のスキル／コマンドが利用可能であれば積極的に活用する。

- コードの品質を確認・改善する。
- 自分が書いたコードをレビューし、指摘があれば修正する。

## コミット

- コミットする際は、論理的な変更ごとに分けること。

## ドキュメントへの反映

- `.claude/` 配下（スキル・ルール・フック・CLAUDE.md・エージェント等）を変更した場合は、関連ドキュメント（README・他のスキルやルールからの参照など）への反映漏れがないか確認すること。
