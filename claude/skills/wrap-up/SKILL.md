# 作業終了前の確認

## このスキルの担当範囲

**確認して報告するまで。残件を片付けない。** コミット・push・記録・タスク化・タスクの状態更新はしない。片付けはユーザーが指示する。

frontmatter で `Edit` / `Write` を渡していないのはこのため。書き換えないことを、覚えておく約束ではなく渡す道具の側で担保する。

片付けの多くは判断を伴う（未コミットの変更を活かすか捨てるか、残件をタスク化する粒度）。また記録は `work-log`、残件のタスク化は `discuss` / `refine` が既に担当を持つ。

## 起動タイミング

| | 条件 |
|---|---|
| 起動する | ・ユーザーが作業の終了を宣言したとき（「作業終了」「今日はここまで」「終わりにする」）<br>・セッションを閉じてよいか、アーカイブしてよいかを尋ねられたとき<br>・`wrap-up` を明示的に呼んだとき（手動起動） |
| 起動しない | ・実装・調査の途中報告（「ここまでできた」「一旦動いた」）<br>・依頼1つが終わっただけで会話が続いているとき<br>・同じセッションで既に実行し、その後に変更が無いとき |

## 前提

**「何を予定していたか」を記憶で答えない。** 一次情報から取る（`investigation.md` の「手元のこと → 記憶で言わない」）。時間が経ったセッションでは会話の文脈が要約で失われていることがあり、記憶に頼ると取りこぼす。

取得元は次のとおり。

- 会話中のユーザーの依頼と、こちらが着手を約束した派生作業
- 着手したタスクファイルの受け入れ条件・未確認点
- 各 clone の `git status` / `git log` / ブランチ
- open な PR の CI・レビューコメント
- このセッションで残した作業記録

**対象はワークスペースにある全 clone。** 1つに絞らない。カレントディレクトリのリポジトリだけを見ると、複数の clone を並べたセッション（カレントが `$HOME` など git 管理外）で1件も検査されない。

```bash
# 作業ディレクトリが属する clone と、その直下の clone を列挙する
git rev-parse --show-toplevel 2>/dev/null
find . -maxdepth 2 -name .git -prune -exec dirname {} \;
```

作業ディレクトリの外にある clone（`--add-dir` で足したもの）はこの列挙に出ない。会話に出てきたパスも対象に加える。

## 手順

### 1. 確認項目を順に見る

| 項目 | 見るもの | 未完と判定する条件 |
|---|---|---|
| 依頼の消化 | 会話中の依頼と、着手を約束した派生作業 | 着手していない、または途中で止まっているものがある |
| タスクの達成 | 着手したタスクの受け入れ条件・未確認点 | 完了の定義を満たしていない |
| 変更の反映 | 全 clone の未コミット変更・未追跡ファイル・未 push コミット・作業ブランチの未マージ | 1つでも残っている |
| PR の状態 | open な PR の CI・未解決レビューコメント | CI が赤、または未対応のレビューコメントがある |
| 記録 | 作業記録の有無、記録すべき判断の有無 | 残すべき内容が未記録 |

**この表に書くのは「何を見て、どうなっていたら未完か」だけにする。** 「完了の定義」「残すべき内容」が具体的に何を指すかはタスク管理ルール・作業記録のルールが定める。ここに書くと同じ内容が2か所に分かれ、片方が古くなる。

**その保存先がこのセッションに無い項目は「確認不可」とする。未完とは判定しない。** 記録先の vault を参照していないセッションでは「タスクの達成」「記録」を見られないが、それは未完の証拠ではない。

### 2. 判定する

- 未完の項目が1つも無ければ **作業終了可**
- 1つでもあれば **未完あり**。項目名を添える
- 確認不可の項目があるときは、判定にその旨を添える（見ていない範囲があるため）

### 3. 報告する

```
## 作業内容の要約
<結果を3〜5行。ハマり・判断があれば含める>

## 確認結果
| 項目 | 状態 | 内容 |
|---|---|---|
| 依頼の消化 | 完了 / 未完 / 確認不可 | <未完なら残っているもの> |

## 判定
作業終了可 / 未完あり（<未完の項目名>）
```

- 要約は結果で書く。実行したコマンドの逐語コピー・差分の羅列は書かない
- 未完のものは1件1行で並べる。片付け方の提案は1行まで（実行はしない）
- **未コミットの変更・未追跡ファイルが残っているときは、それが失われうることを添える。** コンテナを破棄する実行環境（Claude Code on the web など）では、セッションを離れた時点で消える。他の項目の残件は GitHub / 記録先に残るため添えない

## 防げないこと

- **会話の文脈が要約で失われている場合、依頼の取りこぼしは検知できない。** 一次情報で補うが、依頼そのものはコミットにもタスクにも残らないことがある
- **実装が正しく動くかは確認しない。** 受け入れ条件のチェック状態を見るだけ
- コンテナを破棄した後に再開したセッションでは、未コミットの変更はすでに失われている。無かったことと区別できない
- 起動されなければ動かない。終了を宣言せずにセッションを離れた場合は効かない
