# 食事管理

献立の設計・買い物メモの作成・実施記録の手順と書式を定める。

## このスキルが持つもの・持たないもの

本スキルは **「どう進めるか」と「どう書くか」だけ**を持つ。

次の2つは持たない。**保存先や参照先を本スキルに書き込まないこと。**

| 呼び方 | 中身 | 決めるもの |
|---|---|---|
| **食事方針** | 健康上の制約、調理環境の制約、1食あたりの基準量、苦手な食材、運動の条件など | プロジェクト側の指示 |
| **実施記録の残し方** | 食べたもの・在庫の変化・判断の理由をどこへどう残すか | プロジェクト側の指示 |

どちらも、プロジェクトの `CLAUDE.md` / `.claude/rules/` / ユーザーからの指示で決まる。**指示が無ければユーザーに確認する。** 特定のリポジトリやツールを前提にしない。

方針そのものが変わったときは、本スキルではなく食事方針の置き場所を更新する。

## 情報の置き場所

役割で分ける。**同じ内容を複数の場所に書かない。**

| 置き場所 | 何を書くか | 読む人 |
|---|---|---|
| カレンダーの予定「献立」 | その日に実行することだけ。食事ごとに材料と作り方 | その日に作って食べる人 |
| カレンダーの予定「買い出し」 | 買う物と、選ぶときの判断材料 | 店頭にいる人 |
| 食事方針の置き場所 | 共通ルール・方針・制約・基準量 | 献立を考える人 |
| 実施記録の置き場所 | 実施した記録と、判断の理由・経緯 | 後から振り返る人 |

## 献立を組む手順

**順序を守る。特に手順1と手順4を飛ばさない。**

### 1. 在庫を確認する

手元にある食材と残量をユーザーに聞く。**推測で埋めない。** 過去の記録から残量を推定した場合も、確度が低ければ確認する。

### 2. 食事方針を読む

プロジェクト側が示す置き場所から、方針・制約・基準量を読む。置き場所が分からなければユーザーに確認する。

### 3. 予定を確認する

対象日のカレンダーを見て、献立の制約になる予定を拾う。

- 勤務形態（自炊できる食事、昼休憩の長さ、運動の可否が変わる）
- 夜の予定（食事の時刻が遅くなる、調理時間が取れない）
- 翌日の外出（前夜を重くしない）

### 4. 献立を組み、材料を積み上げて在庫と突き合わせる

**全食分の材料使用量を合計し、手順1で確認した在庫と照合する。** これを省くと次の事故が起きる。

- 在庫があるものを買い物リストに載せる
- 切らしている食材に気づかないまま献立に入れる
- 献立側の分量が在庫と合わない

不足分を買い物メモの「必ず買う」へ、在庫がある分を「買わなくてよいもの」へ振り分ける。

### 5. カレンダーに登録する

下記の書式に従う。

### 6. 記録する

決めた内容と判断の理由を、プロジェクト側が示す方法で記録する。

## カレンダーの書式

### タイトル

献立は `献立`、買い物は `買い出し`。**「N日目」のような通し番号を付けない。** 終日予定なので日付で識別できる。

### 色

食事関連の予定は**緑**にする。他の予定と一目で区別するため、新規に登録するときも既定の色のままにしない。

- Google カレンダーの場合は `colorId` に `2`（セージ）を指定する
- 「献立」「買い出し」の両方に同じ色を使う

### 献立

食事ごとに **【材料】→【作り方】** の順で書く。

```
■ 昼食：月見うどん
【材料】
・冷凍うどん 1玉
・冷凍ほうれん草 ひとつかみ
・卵 1個
・めんつゆ 適量
・すりごま、生姜、七味 各少々
【作り方】
1. 冷凍うどんと冷凍ほうれん草を耐熱皿にのせ、ふんわりラップで600W 4〜5分
2. めんつゆを回しかけ、生卵を落とす
3. すりごま・生姜・七味で味を調える
【メモ】
・（実行時に必要な注意だけ書く。取り置き・持ち越し・加熱の加減など）
```

- **材料は分量つきで列挙する。** 作り方を読まなくても、何をいくつ用意すればよいか分かる状態にする
- 手を動かす順に番号を振る

### 共通ルールを予定に書かない

方針・制約・基準量（調理器具の制約、苦手な食材、運動の条件など）を予定の説明欄に書かない。毎日同じ前提を繰り返すぶん冗長になり、その日に必要な情報が埋もれる。

共通ルールは献立を組む時点で反映されていればよく、実行時に読む必要がない。**予定には適用した結果だけを書く。**

```
悪い例: 【共通ルール】運動は出社日以外に行う。今日は出社日なので行わない
良い例: 出社日のため運動は行わない。バナナは朝食で食べる
```

### 買い物メモ

```
■ 必ず買う
□ 卵 1個（6個入りパックでよい。5個は余る）
　→ 月見うどんで1個だけ使う。冷蔵で2〜3週間もつので余りは以降へ
□ カット野菜（キャベツ・もやし）1袋 200〜250g
　→ 初日の夕食に半量、翌日の夕食に残り半量（ちょうど2食分で使い切り）

■ 残量を見て判断
□ ヨーグルト
　→ パックの残りが2回分（約200g）に届かなければ買い足す

■ 在庫があるため不要
・ポン酢 … ストックあり
・パスタ … 100gの束が6つあり、使うのは1束だけ
```

- **品目ごとに「何食分・どの食事で使うか」を1行添える。** 買う量の妥当性を店頭で判断できるようにするため
- **数量は実数で書く。**「1パック」「1袋」で終わらせない。献立で使う実数・売り場の最小単位・余る量を書く
- **「買わなくてよいもの」を理由付きで残す。** 在庫があるもの、献立から外したものを消さずに列挙しておくと、店頭で迷わず、判断の経緯も追える
- 選び方に迷う品（初めて買う調味料など）は、選ぶ基準を箇条書きで添える

## 献立を変えたとき

**1食変えると材料の使用量が変わり、他の予定へ波及する。** 変更したら次を取り直す。

- 買い物メモ（不要になった品、新たに要る品）
- 前後の日の献立（持ち越し・取り置きの前提が崩れていないか）
- 在庫の見通し（使い切りの計算が合っているか）

## 実施を記録するとき

ユーザーから食事の実施報告（写真を含む）を受けたら、プロジェクト側が示す方法で記録する。

- 実際に作ったもの。**献立と違う点があればそれを書く**（代用した調味料、欠けた品、追加した一皿）
- 在庫の変化と、次に使い切る予定の食材
- 判断したことと、その理由

**推測で補わない。** 写真に写っていないものを食べたと書かない。確認が要る場合はユーザーに聞く。
